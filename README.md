## How I approach quality

- Start with customer and business risk before choosing what to automate.
- Keep test intent visible and move repeated technical details into reusable components.
- Use API and database checks where the UI alone cannot prove the result.
- Separate smoke feedback from broader regression coverage.
- Treat screenshots, traces, logs and test counts as part of the framework—not an afterthought.
- Write documentation so another tester or developer can continue the work without a handover meeting.

## AI-assisted quality engineering

I am developing practical ways to use AI in testing while keeping human judgment and verification at the centre of the process.

My current focus includes:

- using GitHub Copilot to accelerate test scaffolding, refactoring and documentation while reviewing every change
- connecting tools and test context through Model Context Protocol (MCP)
- using Langfuse concepts to trace prompts, model responses, latency, cost and failures
- designing repeatable evaluations for LLM response quality and regression
- testing AI features for unsafe input, inconsistent output and observability gaps

I see AI as a way to improve coverage and investigation speed—not as a replacement for thoughtful test design.
